# 2026-10-25 二サイト改善レビュー

AIが専門家10分野・辛口批評家3つの視点を使って実施した模擬レビュー。実在の専門家・Google審査担当への相談や、審査合格の予測ではない。点数・合格率の作り話は用いない。

## 専門10分野の指摘と対応

| 視点 | 日付まちがい防止ナビ | デジタル容量設計室 |
|---|---|---|
| 1. プロダクト | 換算だけでは確認後に使う理由が弱い。仮予定の.ics保存を追加 | 単発の電卓が3つ並ぶ。保存容量をバックアップへ引き継ぐ導線を追加 |
| 2. 初心者UX | 入力例が1つのみ。年越しとホテル8時間待ちの例を追加 | ビットレートが分からず止まる。ファイル容量・時間から逆算し反映する補助を追加 |
| 3. モバイル | ノッチと下部の干渉余地。safe-area対応と追加ボタン44px以上 | 同じくsafe-area対応。結果メモ欄は幅内表示 |
| 4. アクセシビリティ | エラー時のフォーカス・結果の見出し維持。ファイル生成失敗を文字で案内 | 結果へフォーカス可能に。コピー不可時の選択用テキストを追加 |
| 5. 計算品質 | 年越し・うるう年・端末TZ不変性を維持。UTCによるICS日時の試験を追加 | MB/MiB逆算と二重音声加算を防止。容量引継ぎの境界・不正入力試験を追加 |
| 6. 信頼性 | 古い結果の予定ファイルを再利用させない。入力変更でリンク無効化・URL破棄 | コピー中に入力が変わっても古いメモを再表示しない。独立した任意の逆算欄は主計算の必須にしない |
| 7. 情報設計・SEO | 同じ瞬間を示す24:20・翌00:20・00:20の比較をホームへ掲載 | 使い方・プライバシーを実装と一致。水増しの類似ページは追加しない |
| 8. データ保護 | .icsは端末内で作成。取込先のカレンダーの扱いを説明 | 合計容量だけを明示操作でフラグメントに付け、読込後に削除。入力の永続保存なし |
| 9. 広告ポリシー | 所有確認用meta・ads.txtを維持、入力操作に重なる広告は追加しない | 管理画面で本人確認済みのIDを本番の所有確認meta・ads.txtへ適用。広告配信は開始しない |
| 10. 運用保守 | 原稿生成元を更新しdistへ再生成。料金表や運行ダイヤの固定値は増やさない | srcとビルダーを正本に更新。外部依存・料金情報なし。CIと本番両方で検証 |

## 辛口批評家3名の視点

1. **独自性批評**：「既存の日時変換・容量電卓でも代用できる。見た目だけの改装では弱い」。予定メモ、ホテル待ち時間例、実ファイルからの逆算、次の計算への引継ぎに実用を絞った。ただし検索流入・再訪・有用性の市場評価は未計測。機能追加だけで承認されるとは言えない。
2. **誤解批評**：「日付ナビが乗る日を保証すると誤認される。容量の小数は精密な実測値に見える」。保証的なヒーロー文言を緩和し『入力表記を換算した日時』へ変更。予定はTENTATIVE・30分の仮枠で、集合・到着時刻や予約確定ではない。容量のメモにも入力条件と目安を付記。
3. **実証批評**：「自動テストだけでは、スマホで保存・コピーできるとは言えない。問い合わせにGitHub登録が必要」。DOM模擬試験と実ブラウザー試験は区別。スマホでのICS取込・ノッチ・共有先の表示は未検証。GitHub Issuesの投稿ハードルは残る。別サイト用に提供されたメールを無断転用しない。

## 検証方法と残る確認

- Nodeの計算試験、静的リンク検査、新機能のDOM模擬試験を実施。新機能のフロー試験は実際のブラウザー描画・OSダウンロードの検証ではない。
- 日付：80テスト、静的146項目。ICSはUTC日時、CRLF、UTF-8の75オクテット折返し、年越し・うるう年・上限年、編集後のリンク破棄、コピー拒否時の代替を検査。
- 容量：45テスト。逆算値、音声重複防止、8.25 GB→バックアップ1か所9.9 GB、極小・最大容量、入力変更時のメモ無効化、不正な引継ぎを検査。
- 両サイトの配備結果と公開ファイルの一致はリリース時に別記。スマートフォンの表示・ICS取込は未検証。新機能の実機確認を推奨する。
- AdSense審査申請はこのコード変更とは別工程。管理画面はこの実行環境で操作できないため、申請済みとは記録しない。
