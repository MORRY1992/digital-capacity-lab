# 運営・公開後の保守

## 稼働確認

実装済みのGitHub Actionsは毎日08:17 JST、毎週金曜09:47 JSTの指定。GitHubの実行遅延があり、時刻厳守を保証しない。公開repoの標準runner、または無料枠確認済みのprivate repoでのみ動作。リポジトリ登録後に実行履歴を確認する。公開URLを設定するまでは本番HTTP検査は実行されない。

毎回：再ビルド→計算・静的テスト。定期/手動時はSITE_URLがあれば公開20エンドポイントへGETし、HTTP200、HTML、canonical、サイトマップ、試験済み計算コードとの一致を検査。広告は実行せず、広告クリック・広告表示を作らない。入力値や個人データを送信しない。

週次も同一の全回帰検査を実施する。外部依存パッケージはない。GitHub ActionsアクションとNodeの更新・セキュリティ情報の評価はWorkでの保守時に行う。自動で技術記事を調査する設定ではない。

## 記録・通知

テスト結果はActionsログ、HTTP検査はJob summary。失敗時は非0終了。GitHub通知設定によるメール等の受信は本人アカウント側で有効化・受信確認が必要で、現状未検証。独自メール・Slack通知は送信しない。ログ保持量や無料使用量を定期確認する。

## 障害の対処

1. Actionsの失敗ステップを確認。公開URL/HTTP応答/最新のCloudflare deploymentを確認。
2. 計算エラーは同じ入力をローカルで再現し、独立した期待値をテスト追加→修正→全テスト。
3. 配信障害はCloudflare側のビルドログと環境変数を確認。必要なら新サイトの直前正常バージョンにロールバック。既存他サイトは触らない。
4. 本番URLで再確認。完了・未検証を分けて報告する。Workが閉じている間の自動修正はない。

## 月次分析（データ接続後）

Search Console：クリック・表示回数・検索語・掲載ページ。AdSense：PV、ページRPM、推定収益。配信基盤：転送量・ビルド数。分析タグは現状なし。取得権限がなければ「未取得」と記録。アクセス0や収益0と推定しない。自動的に毎月分析するタスクは未登録。

改善順序：入力完了率を阻害する不具合→説明不足→実際に流入した検索意図への解説拡充→適切な広告枠配置。検索量や広告単価の仮説は実測と分ける。

## 制約

Time Atlasと余白の寝室は現在の管理先・機能・稼働未確認。検索から該当資料を特定できず、接続GitHubには既存3repoだけが表示された。今回は時差・日付・睡眠等を扱わず、容量領域に限定している。全機能の重複監査完了とはしない。
